## Data model (Firestore, project alice-ai-office-hub)
- `trustSignups/{id}` — {name, email, tierInterest, uid|null, source, createdAt}. Public create via validator only; read = master users.
- `trustUsers/{uid}` + `builds/{id}` subcollection — profile (incl. `paidAccess`, **admin-write-only** in the rules — owners can never set or change it on their own doc), trainingProgress map, saved builds {name, grantor, state, docText, createdAt, updatedAt}. Owner read/write (profile minus paidAccess); master users read + write.
- `trustRecords/{id}` — {uid, kind, label, payload, createdAt} vault/CRM snapshots and Land Trust distribution schedules (kind `land-trust-distribution`). Owner create/read/delete; master users read.
- `trustSiteContent/main` — {headlineHtml, subtitle, priceDisplay, priceAnnual, checkoutUrl, checkoutMonthlyUrl, checkoutAnnualUrl, sb24Url, bannerText, bannerOn, updatedAt, updatedBy}. Public read; master-user write. Paid tier: $50/mo or $299/yr (priceDisplay / priceAnnual; static defaults in trust-app.js until a master user saves content). The freemium gate's plan buttons use `checkoutMonthlyUrl` / `checkoutAnnualUrl`, falling back to the single `checkoutUrl`; until the Whop products exist all stay empty and the buttons run the honest placeholder (free sign-up + "checkout opens at launch"). **No checkout link is invented anywhere.**

## Remaining gates (one step each, all Madison-side)
1. **Vercel project** — the stored deploy credential can deploy to the
   existing Alice project but cannot create projects (403 on
   POST /v11/projects). In the Vercel dashboard (team capital7lllc-1439):
   Add New → Project → name it `build-a-trust-24`, framework "Other".
   Then the deploy below runs as-is, and the domain
   `buildatrust24.aliceaihub.xyz` attaches to the new project via API
   (Vercel DNS already serves the zone; an exact subdomain assignment
   overrides the Alice project's `*.aliceaihub.xyz` wildcard for this
   host only — Alice and its tenants are unaffected).
2. **Firebase Auth authorized domain** — Authentication → Settings →
   Authorized domains → Add `buildatrust24.aliceaihub.xyz`. (Verified
   2026-10-26: current list is localhost, the firebaseapp/web.app hosts,
   and aliceaihub.xyz.) Without this, Google sign-in returns
   auth/unauthorized-domain; the page explains that in plain language.
3. **Google provider** — Authentication → Sign-in method → Google →
   Enable (if it isn't already). If it is off, sign-in returns
   auth/operation-not-allowed and the page/admin say exactly that.
4. **Firestore rules publish** — Firestore Database → Rules → select-all
   REPLACE with this folder's `firestore.rules` → Publish. Until then,
   the new collections are default-denied: sign-up capture, saved builds,
   and admin reads/writes stay dark (the page itself works exactly like
   the static site). The file compiles clean in the local emulator rig.
5. **Whop checkout (later)** — when the paid-tier products exist ($50/mo and $299/yr), paste the
   checkout URLs into /admin → Site Content (monthly + annual fields). Nothing to do now.
6. **Marking a customer paid** — set `paidAccess: true` on their `trustUsers/{uid}` doc
   (Firestore console or a master-user write). The rules reject any owner attempt to
   create or change that field, so there is no self-unlock path. Re-publish `firestore.rules`
   for the tightened trustUsers block.

## Deploy (after gate 1)

import hashlib, json, pathlib
files = ["index.html","admin.html","trust-config.js","trust-app.js","admin.js","vercel.json"]

PY
